1. **OpenClaw #145484 manages and reloads plugins without Gateway restarts (33,552 core lines across 100 files); #145648 swaps the tool set inside an active conversation before the next model request; #145816, #146275 and #146072 clean up behind them** #145484 (merge-risk: compatibility, built on yesterday's #144252) says it plainly: plugin changes take effect 'without restarting the Gateway or disconnecting clients'. One Gateway-owned prepare, drain, publish and retire lifecycle replaces the old restart signalling and UI restart waits, unaffected instances are retained, per-instance module capture works around Bun reporting success while keeping old modules, and a failed activation gets a clear recovery action. #145648 (3,972 lines across 55 files, security label) pushes this into live conversations: the runner owns one continuation across plugin generations, settles admitted Code Mode work, records completed results, releases the old generation and acquires current tools before the next model request; confirmed sends and pending media have separate owners so completed actions are not replayed and messages are not duplicated. #145816 fixes missing Bun dependencies, stalled management requests and resources left stopped after a failed replacement; #146275 gives startup and reload one sparse overlay merger so a source-only config edit is no longer rejected as superseded by startup auth overrides; #146072 removes 298 duplicated lines. For us: our 'configuration changes drain then restart' line is old wording as of today. The side effect matters more: swapping the tool set mid-conversation means a full DeepSeek prefix-cache miss from the tools segment onward, so the restart time saved by hot reload has to be re-costed in tokens against fact-deepseek-prefix-cache-tool-order. — [source](https://github.com/openclaw/openclaw/pull/145484)

2. **OpenClaw #145426 (P0): one secondary agent's divergent SQLite copy used to keep the whole Gateway from starting; startup now builds a process-scoped admission map that refuses per agent instead of failing as a whole** 2,015 core lines across 26 files, merge-risk: compatibility, fixes #144689. When a multi-agent installation updated, one secondary agent's directory held a divergent copy of another agent's database, healthy agents could not serve and Doctor could not finish independent repairs. The fix is not file repair: startup derives typed ownership refusals from the configured database files into one process-scoped admission map, and routing, model and chat-metadata preparation, session listing and recovery, status, Doctor and scheduled work all consume that one decision; default or system-agent and shared-state failures stay fatal, divergent files are preserved, and Doctor uses the existing recovery owner's inspection and quarantine gate. For our multi-tenant cluster this is today's most direct item: one tenant's corrupted state may refuse only that tenant, and 'which failures are Gateway-fatal and which are agent-level refusals' must be written down at the admission layer rather than decided by whichever module throws first. #145541 the same day is the companion: startup version checks used to copy whole agent databases and now read the header through a read-only worker. — [source](https://github.com/openclaw/openclaw/pull/145426)

3. **Hermes #109440 (P1, open): hermes chat -q -m <direct alias> sends the alias's API key to the default provider's host, reproduced on v0.21.2; the same class of leak was fixed two months ago only on the /model and -z paths** Labels area/auth plus sweeper:risk-security-boundary. The reporter separates 'alias resolution' from 'credential routing', which is exactly right. It shares a root with yesterday's #99523, where five different paths could pick Responses by accident: when one provider has several entry points, the (host, key) pair must be computed together by one owner, and any entry point that computes host or key alone is a leak surface. 4. **Three on Cloudflare agents main: #2245 agents/queue moves every hand-rolled queue in Agent and Think onto the Lifecycle job queue (alarm loop, one item at a time in push order); #2179 extracts state into a capability; #2257 makes WebSockets own the Agent protocol's state sync** #2245 (3,272 core lines across 24 files): Queue is vocabulary over the Lifecycle job queue (#2175), each pushed item is one job due now, Lifecycle's alarm event loop runs items one at a time in push order with the existing retry policy, deadman pre-arm, hung recovery and memory-limit breaker, callbacks are registered in the constructor and typed at declaration and push, and Agent bridges its name-based this.queue('method') through a composition-root resolver exactly like Scheduler. #2179 (959 lines across 9 files): _setStateInternal used to do validate, persist, broadcast and notify in one method inside the Agent god-class; now any Lifecycle host gets durable, validated state without inheriting Agent, with the public API and wire protocol unchanged. #2257 (1,269 lines across 12 files) moves the Agent protocol's state sync and per-connection flags out of Agent into the WebSockets capability, so a plain DurableObject gets useAgent().state and setState(). 5. **OpenClaw #146369 (P1): agents inside the Gateway opened a fresh WebSocket back to the same process for every hosted tool call, now routed in-process; #146273 reuses the worker pool for repository reads (1 metadata, up to 2 content, 1 maintenance)** #146369 (2,884 core lines across 54 files, closes #100941): agents running inside the Gateway could stall or get connection errors while making parallel automation, node, approval, question, message and session calls, because each opened a fresh WebSocket back to the same process, and cleanup plus memory and session lookups had the same avoidable round trips. ## The Pattern

Today's strongest signals are three **boundaries**.

The first is the **boundary of hot swapping**. OpenClaw #145484 spends 33,552 lines folding the plugin lifecycle into a Gateway-owned prepare, drain, publish and retire, and #145648 pushes it into live conversations: the old generation settles admitted work first, and new tools are acquired only before the next model request. Yesterday's open question has an answer: 'drain then restart' is being replaced, at the cost of forty thousand lines and a security label. What matters more for us is the side effect. Swapping the tool set mid-conversation is, for a DeepSeek prefix cache, a full miss from the tools segment onward. The restart time hot reload saves may be paid back twice on the token bill.

The second is the **boundary of failure**. The story in #145426 (P0) is plain: a secondary agent's directory held a divergent copy of another agent's database, and the whole Gateway would not start. The fix is not file repair but a process-scoped admission map built at startup that writes down which failures are Gateway-fatal and which refuse only that one agent. That is the first principle of multi-tenancy: the fault domain is defined at the admission layer, not by whichever module throws first. #145506 is its mirror image: a local capability lost after compaction was classified as a model failure and triggered a fallback that should never have fired. Get the classification wrong and the fault domain is wrong.

The third is the **boundary of credentials**. In Hermes #109440, chat -q -m <alias> sends the alias's key to the default provider's host. The same class of bug was fixed two months ago on the /model and -z paths; this path was missed. The reporter puts it precisely: alias resolution and credential routing are two different things. Read alongside yesterday's #99523, where five paths could pick Responses by accident, the conclusion is one sentence: the (host, key) pair must be computed together by one owner, and every extra entry point is an extra leak surface.

Cloudflare is working the other side of the same problem, decomposing Agent into State, WebSockets and Queue capabilities so that 'serial within a tenant' goes from our judgment to a primitive: an alarm loop running one item at a time. And DeepSeek v4.1-Flash's encoder-decoder architecture is only a headline, yet it sits directly on our bill, which makes it the one item today that has to be verified.

## Clusters and reliability

- [OpenClaw #144637 reef: bounded inbound stores correctly reject-new on capacity, but capacity errors surfaced as transport faults, so the shared inbox tore itself down and re-polled from the unchanged cursor, head-of-line blocking every peer and re-entering handling for an already dispatched entry](https://github.com/openclaw/openclaw/pull/144637) — The fix makes delivery capacity a parked, retry-safe domain state: a capacity error parks the affected entry instead of unwinding the shared inbox, and the persisted durability contract is untouched.
