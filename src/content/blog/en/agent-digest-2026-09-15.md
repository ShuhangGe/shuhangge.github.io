## TL;DR — Today's Overview

> The guards are in the wrong place: redaction skips persistence, the denylist covers reads only, and spawn quietly tightened

1. **Hermes: redaction does not cover persistence — a credential pasted into a chat lands verbatim in state.db and its FTS5 mirrors** Even with `security.redact_secrets: true`, redaction today applies to four exits — terminal output, logs, display and `debug share` — and not to the write path: `append_message` in `hermes_state_messages.py` on current main (ee44529) stores rows "as sent except lone surrogates". So a single paste, say a Telegram bot token copied from BotFather, ends up in the user message `content`, in every later assistant `tool_calls` entry that uses it, in `reasoning` / `reasoning_content`, and in the FTS5 content tables mirroring those columns — four copies. Downstream, `hermes backup` and `hermes sessions export` without `--redact` carry them all out. We keep full model-visible/logged session transcripts for our evidence gate, which puts us on exactly this spot: redaction has to live inside the write-to-database function, and the full-text index counts as its own separate copy. — [source](https://github.com/NousResearch/hermes-agent/issues/110416)

2. **OpenClaw 2026.9.4: sessions_spawn caps children at the caller's tool surface, with no changelog and no migration** Since 2026.9.4, resolving a `sessions_spawn` child's tools additionally applies the spawning session's own resolved tool list as an inherited allowlist — a caller tool-policy ceiling. A coding worker whose `agents.entries.*.tools.allow` explicitly names `read, write, edit, apply_patch, exec, process` therefore cannot start at all if its parent session's surface lacks `group:fs` / `group:runtime`, failing with `No callable tools remain after resolving explicit tool allowlist (...; inherited tools.allow: ...)`. That kills a common topology outright: a messaging/PA main agent on the Claude CLI runtime does its file and exec work through the CLI harness, so its OpenClaw-side tool surface is empty by design. The same config worked on 2026.9.3. The issue is labelled P1, impact:security and needs-live-repro, and is still open. — [source](https://github.com/openclaw/openclaw/issues/147857)

3. **Hermes: the sensitive-path guard was mounted on two of four fs readers, so fs_read_text returned auth.json to the dashboard** `_is_sensitive_path` was documented in #57505 as the read-side guard for list, read and download, but only `fs_read_data_url` and `fs_download` actually called it. As a result `fs_read_text` returned the contents of `.env`, `auth.json` and `mcp-tokens/*` straight to an authenticated dashboard session, and `fs_list` happily enumerated them. The fix (#110513, 35 core lines) moves the check into `_fs_regular_file` — the resolver every fs reader goes through — drops the two per-handler copies, and makes `fs_list` filter on the same predicate. This is a live external instance of our judgment-gates-bind-to-real-consumption-point: the guard was correct and the documentation was correct; it just was not mounted on the shared path. — [source](https://github.com/NousResearch/hermes-agent/pull/110513)

4. **Hermes: the write denylist drifted from the read denylist, letting write_file overwrite vault.key and webhook HMAC secrets** `is_read_denied` refuses eight HERMES_HOME stores (`auth.json`/`auth.lock`, `webhook_subscriptions.json`, `auth/google_oauth.json`, `cache/bws_cache.json`, `vault/`, `browser-profile/`, `.env`, `.anthropic_oauth.json`), while `is_write_denied` refuses only three of them. The agent's `write_file` / `patch` can therefore overwrite auth tokens, webhook HMAC secrets, Google OAuth, the Bitwarden plaintext cache, `vault/vault.key` and browser cookies. The reporter reproduced it on current main by pointing `HERMES_HOME` at a temp profile. Two hand-maintained mirror lists will always drift, which belongs directly in our own gate rules: reads and writes share one predicate, and there is no such thing as a list you remember to keep in sync. — [source](https://github.com/NousResearch/hermes-agent/issues/110464)

5. **Hermes v0.21.3: state.db handle ownership consolidated — readers attach read-only, in-process writers share one registry handle** The tag rolls roughly 338 PRs since v0.21.2 to downstream consumers — Docker images, Hermes Cloud, hosted deployments — where Cloud agents auto-update to the newest release tag. Two pieces are worth copying. #110934 (fixes #100896 and #103339) has the gateway, the dashboard/Desktop backend, ACP and CLI readers attach read-only while in-process writers share the registry handle, so the `N live SessionDB handles` precursor stops firing on a healthy topology. #110061 (fixes #55712) coalesces concurrent requests carrying the same rotating refresh token across both gateway refresh paths — the cookie gate and the Desktop native bearer route — so a Desktop wake burst can no longer replay an already-rotated token into the Portal's reuse detection and revoke the whole session; refresh also moved off the event loop, so a slow identity provider no longer freezes `/api/status`. It pairs with hermes-portal#1209 on the Portal side: a sliding 30-day idle horizon and a 5-minute rotated-token grace. — [source](https://github.com/NousResearch/hermes-agent/releases/tag/v2026.9.14)

6. **OpenClaw: in one authenticated admin conversation, the automation scope differs by model route (Claude CLI/MCP vs OpenAI)** The report says that in one authenticated Control UI administrator conversation, the Claude CLI/MCP route received caller-scoped automation access while switching the same conversation to the OpenAI route returned Gateway-wide access. The issue labels itself `NOT_ENOUGH_INFO` — there is no deterministic reproduction on current upstream main yet, and the original Claude-side tool response has not been independently re-captured, so treat the specifics as unverified. It nonetheless asks for maintainer triage with the security owner involved (P2, impact:security, needs-security-review). Even if it is eventually disproved, the question it raises is a hard requirement for us: authorization scope must never be a function of the model route, and the tenant boundary has to be fixed before control reaches a provider adapter. — [source](https://github.com/openclaw/openclaw/issues/147614)

7. **Claude Code v2.1.271: per-command egress allowlists, subagents that can skip CLAUDE.md, and chargeback multipliers up to 10x** Three items land directly on us. First, in auto mode with sandboxing, Bash, PowerShell and Monitor now take a per-command `allowed_domains`: the hosts a command needs are reviewed together with it and opened for that command alone, with other hosts refused — a finer grain of egress control than one allowlist per sandbox. Second, agent frontmatter and the `--agents` JSON gain `omitClaudeMd`, letting custom and plugin subagents run without user, project and local CLAUDE.md while managed policy files still load; that split — policy always loads, user context is optional — is exactly the shape multi-tenancy needs. Third, the `modelPricing` managed setting and the Claude apps gateway `pricing` block accept a `multiplier` above 1 and up to 10, for marked-up internal chargeback. Also shipped: `claude self-hosted-runner --drain-marker-file`, which makes the runner report a SIGTERM exit as a host drain for telemetry, and `--accept-command` on `claude plugin install`/`update`, which accepts exactly the command a previous `--json` run displayed instead of a blanket `-y`. — [source](https://github.com/anthropics/claude-code/releases/tag/v2.1.271)

8. **Hermes: tool visibility and tool authorization came from two different sources, so every call the model made hit a 404** A paid Hermes Cloud account on v0.21.2 called `manage_connections(status)` and got back `tool gateway request failed with status 404`, after which the model pointed the user at a Portal Connectors page that also 404s. The gateway is not the bug: it answers 404 to any account the portal has not enabled for connectors, and that is intended. The bug is that Hermes decided whether to advertise the tool from `paid_access` or from a live free tool pool, neither of which says whether connectors are enabled. The fix (#111238, 88 core lines) hides `manage_connections` entirely from accounts that are not enabled. For multi-tenancy this is a hard rule: the tool list a tenant's model sees must be derived from the same authority that will admit the call, or every un-entitled tenant gets a model-visible dead end and the model invents its own recovery path. — [source](https://github.com/NousResearch/hermes-agent/pull/111238)

9. **OpenClaw #147276: a Dockerized Gateway starting sibling sandboxes over the host socket now requires bind-backed managed mounts** This is our exact shape: a Gateway in a container starting sibling sandbox containers through the host Docker socket. The defect was that workspace files and materialized skills went missing inside the sandbox. The fix makes shell and browser managed mounts resolve to the same bind-backed workspace, agent and skill files that the Gateway's own file tools see, while read-only mounts stay read-only. Managed sources must now be bind-backed: volume and tmpfs layouts report an actionable error instead of half-working silently, a retained sandbox whose mounts differ has to be recreated with the reported command, and the Gateway needs a restart after its Docker mounts or connection change. Browser CDP connectivity over the default Compose bridge remains a separate known limitation. Labelled P1 with merge-risk: compatibility. — [source](https://github.com/openclaw/openclaw/pull/147276)

10. **cloudflare/agents #2244: a failing bookkeeping cleanup turned a successful run into a failed return** When finalizing, `runFiber` deletes the completed legacy bookkeeping row from `cf_agents_runs`. If that delete failed, the resulting `SqlError` replaced the fiber body's real outcome on its way to the caller: the body returned `"completed"` while the RPC rejected with a simulated fiber cleanup failure. The fix downgrades the delete to best-effort finalization — log it, leave the row for the existing recovery pass, do not replace the outcome. The regression proves it with a real SQLite trigger that fails only the final `cf_agents_runs` delete. At 66 lines across 3 files it is small, but it is a textbook sample of a bug class our own queue can host: in any record-the-result-then-clean-up sequence, the cleanup's failure must never become the operation's outcome, or a caller retrying on that error re-runs work that already completed. — [source](https://github.com/cloudflare/agents/pull/2244)

## The Pattern

## Where the guard is mounted matters more than what it says

Hermes produced three instances of the same failure in a single day.

**Redaction does not cover the write path.** `security.redact_secrets: true` governs terminal output, logs, display and `debug share`, but not persistence — on current main `append_message` stores rows "as sent except lone surrogates". One pasted token therefore lands in the message `content`, in every later `tool_calls` entry that uses it, in `reasoning_content`, and in the FTS5 content tables mirroring those three columns: four copies from one paste, all of them carried out by `hermes backup` and by `hermes sessions export` without `--redact` (#110416).

**The guard was mounted on two entry points.** `_is_sensitive_path` describes itself as the read-side guard for list, read and download, yet only `fs_read_data_url` and `fs_download` called it. `fs_read_text` returned `.env`, `auth.json` and `mcp-tokens/*` to an authenticated dashboard session while `fs_list` enumerated them. The fix moves the check into `_fs_regular_file`, the resolver every reader must pass through (#110513).

**Two lists drifted.** `is_read_denied` refuses eight stores; `is_write_denied` refuses three. So `write_file` / `patch` can overwrite `vault/vault.key`, webhook HMAC secrets and browser cookies (#110464).

In all three cases the policy itself is correct. What is wrong is the path it hangs on. Our `@shared/judgment-gates-bind-to-real-consumption-point` (asserted 2026-09-08) says self-checks must bind to the real consumption point and that mirror lists are poison; today's evidence pushes the same rule from the checks onto the guards themselves. A guard belongs on the resolver every consumer shares, and reads and writes must run through one predicate.

OpenClaw supplied the matching lesson from the other end on the same day. Since 2026.9.4 a spawning session's resolved tool list is applied as an inherited allowlist to its children, so a messaging/PA main agent on the Claude CLI runtime — whose OpenClaw-side surface has no `group:fs` or `group:runtime` — fails every spawn of its coding workers with `No callable tools remain after resolving explicit tool allowlist`. The identical config ran on 2026.9.3, and the change shipped with no changelog and no doctor migration (#147857, P1, impact:security). That lands squarely on OpenClaw's own VISION.md rule that a schema change must ship with `doctor --fix`: tightening the authority surface was treated as a bug fix rather than a schema change.

Three things follow for us. First, put redaction inside the write-to-database function and count the full-text index as a separate copy. Second, let reads and writes share one sensitive-path predicate, and make removing either side turn a test red. Third, derive a child agent's tool authority from the child's own declaration intersected with tenant policy, never inherited from the caller's surface — and when we do tighten it, the same PR must carry a startup test for existing topologies.

## Frameworks

- [OpenClaw #147994: one model can appear as several harness-labelled rows in the picker](https://github.com/openclaw/openclaw/pull/147994) — 5,371 core lines across 66 files. An operator can add `pickerRuntimes` to an exact configured model entry; same-name rows then show with their harness labels and a selection works for both new and existing chats. The configured default is unchanged, and picking Default clears the session selection where the session lifecycle permits, with runtime-owned sessions keeping their locks. The Gateway keeps one canonical model and publishes separately validated runtime choices.
- [OpenClaw #147571: what a subagent is waiting on becomes observable, and execution is separated from result delivery](https://github.com/openclaw/openclaw/pull/147571) — 6,705 core lines across 42 files. Parents and operators previously could not tell whether a child was executing, waiting on another child, awaiting input, or finished but still delivering its result; ambiguous yields and cancellation races stranded work or produced premature parent replies. Now the subagent tools and the Control UI inspector explain what each child is waiting on, support selected-task waits and explicit notify/steer/followup controls, cron follows descendant settlement, and TaskFlow/Lobster resumes the checkpoints it owns.
- [OpenClaw #148261: an internal refactor paving the way for atomic compaction persistence](https://github.com/openclaw/openclaw/pull/148261) — 647 core lines across 14 files, with public SessionManager signatures and SQLite storage contracts unchanged. The goal is a storage operation for compaction accounting that can move into the existing worker owner without calling back into live SessionManager objects during its transaction: the boundary and the accounting commit together under the original writer authority, and the committed parent/version facts are adopted afterwards. It is another monthly confirmation of our judgment-compaction-is-most-reworked-component — this month the rework lands on ownership rather than the algorithm.
- [OpenClaw #147421: Bun substitutes partial implementations for ws and undici, breaking plugin networking](https://github.com/openclaw/openclaw/pull/147421) — Running under Bun, the partial package-entry implementations Bun substitutes for `ws` and `undici` make Browser relay, Mattermost, the Slack relay and API proxying, Reef, Codex inference, Nextcloud Talk and Crabbox hang, ignore proxy options, or fail at startup. The fix publishes the existing gateway-client npm-`ws` loader as the typed `openclaw/plugin-sdk/websocket-runtime` contract and moves Slack onto the shared HTTP/1 environment-proxy dispatcher. Swapping runtimes is not free; this belongs on the ledger when choosing one.
- [OpenClaw #142545: memory dreaming promotion could commit a file past the bootstrap cap](https://github.com/openclaw/openclaw/pull/142545) — Memory Core promotion used a 10,000-character writer default even when the consuming agent injected less of `MEMORY.md`, so its append fallback could commit an oversized file and still mark candidates promoted. The effective writer budget is now the smallest per-file bootstrap cap among agents sharing the canonical workspace; user-authored and ambiguous content is preserved unconditionally, removal of prior machine-generated entries is bounded by `maxPriorEntryLossFraction` (default 25%), and the file and the promotion state commit together.
- [Hermes #111038: Windows llama-server trees are bound by a job object and orphans are reclaimed explicitly](https://github.com/NousResearch/hermes-agent/pull/111038) — 1,137 core lines, fixes #110561. Each Windows router starts suspended, is assigned to a dedicated non-inheritable `KILL_ON_JOB_CLOSE` job, and is then resumed; neither breakaway flag is enabled, and setup failures clean up the suspended child and its handles. The job is retained for the supervisor's lifetime and closed on stop or crash-restart, so a stop during restart backoff cannot resurrect the server. Recovery of older orphans becomes an explicit, identity-checked Turn off action, with router/owner creation times and executable identity recorded.

## Cluster and reliability

- [OpenClaw #148508: execution deadlines belong to the run owner, and duplicate timers are removed](https://github.com/openclaw/openclaw/pull/148508) — 1,330 core lines across 25 files, P1. Long-running work could previously be cut short by a shorter startup, monitoring or wait timeout, lose its configured budget after resuming, or lose its late reply. Now ACP turns and approved command continuations keep their execution budgets, recovered and resumed children retain their saved timeout including an explicit zero, and background-task reviews use the ordinary agent budget; the patch removes ACPX's duplicate turn timers outright. This is the same conclusion our fact-hermes-unified-deadline-primitive records, now reached independently in a second codebase.
- [OpenClaw #147499: entitlement was lost across sessions_yield, so automation management reported Automation not found](https://github.com/openclaw/openclaw/pull/147499) — After an authenticated Control UI administrator waited for subagents with `sessions_yield`, managing existing automations failed with `Automation not found`. Yield closes the original run while child settlement starts a synthetic continuation; the registry now transfers the verified parent entitlement through the committed child batch, and Gateway admission issues fresh management-only grants for the successor. Cancellation, session reset/archive, a new direct user turn and a Gateway restart still revoke the handoff. Asynchronous boundaries eat entitlements — a rite of passage for any orchestration layer with yield and resume.
- [OpenClaw #147887: the session-delivery queue's SQLite moves off the Gateway thread into the shared-state worker](https://github.com/openclaw/openclaw/pull/147887) — 3,552 core lines across 19 files. The session-delivery queue APIs returned Promises while executing SQLite on the Gateway thread, including during retry scheduling and restart recovery. The move preserves deduplication, retry bookkeeping, settlement and restart recovery with no configuration, schema or retained-data migration; producers, recovery, generated-media preparation and the scheduler carry one captured database context through an operation, and scheduler shutdown joins admitted reads and drains before closing the database. It continues yesterday's campaign of pushing SQLite off the Gateway event loop.
- [OpenClaw #148032: recovery no longer decodes every unrelated retained session](https://github.com/openclaw/openclaw/pull/148032) — Main-session recovery validation, release and reservation transitions read and decoded every retained session even when the authoritative lease or reservation was still at its known key, so large unrelated session payloads burned gateway main-thread CPU on routine recovery. The recovery owner now selects the known key first and falls back to the existing inventory search only when the exact identity does not match. The PR states its measurements come from a controlled fixture and that production latency was not measured.
- [OpenClaw #148099: Auto sessions spread across paired devices, as a preference rather than a slot reservation](https://github.com/openclaw/openclaw/pull/148099) — During a burst, Auto piled work onto one paired device and then failed on a capacity change while other hosts still had room. The selector now considers work already admitted by the Gateway when choosing a host, so new sessions spread before worker-slot telemetry catches up, and a device that becomes ineligible before workspace preparation can be replaced once its failed allocation is cleaned up. The PR states plainly that this is a placement preference and not an atomic slot reservation, with the node still admitting each physical worker launch against current capacity — a phrasing worth copying for our own interface docs.
- [OpenClaw #145940: restarts rewrote finished subagent tasks and bumped their flow revisions every time](https://github.com/openclaw/openclaw/pull/145940) — Every Gateway restart rewrote finished subagent tasks and raised their flow revisions despite no new work. The task registry now skips equivalent terminal writes, mirrored flows compare their derived state before writing, stale flows still repair, and failed task notifications can still retry. The PR carries a table from three real Gateway starts per case: revisions went 3 → 4 → 5 before the fix and 5 → 5 → 5 after. An idle restart should produce no state change, which is a directly copyable acceptance form for our own idempotent recovery.
- [OpenClaw #147871: a requested stop surfaced as a SIGTERM failure, and children yielded without collecting background results](https://github.com/openclaw/openclaw/pull/147871) — Stopping a background command before handing work to a child produced a false SIGTERM failure in chat, and a child waiting on its own background command could yield with no completion wake at all, parking the task while its CI watcher retried expired proxy access. The process owner now records an explicit stop request and confirms it against the settled outcome, so a confirmed stop stays visible in tool details without becoming a chat failure; subagents collect their background results before yielding, and CI watchers report proxy-authentication refusal immediately.
- [OpenClaw #139878: startup preflight over many agent databases becomes bounded-parallel at two](https://github.com/openclaw/openclaw/pull/139878) — Gateway startup inspected agent databases one after another, extending startup and update-restart waits on installations with many agent stores. The preflight owner now awaits a pool of two inspections around both the eligible schema child reader and the retained private snapshot path, preserving schema and ownership validation, deduplication, busy timeouts and input-order results. The cost is stated in the PR: two fallback snapshots can coexist, raising peak temporary storage and I/O versus serial inspection. Labelled merge-risk: availability.

## Protocols and the tool surface

- [Hermes #109517: installing a local MCP server folds into manage_connections, with a backend-set deadline on the approval card](https://github.com/NousResearch/hermes-agent/pull/109517) — 2,858 core lines across 13 files. Asking Hermes to add the Linear MCP now goes through the same tool that connects Gmail or Notion, and `setup_mcp` leaves the schema. The PR introduces a connection operation record: one tool call creates one operation carrying its targets, each target's state and a deadline, with the desktop showing an approval card while the model waits. Modelling "install an MCP server" as a first-class, model-initiated, human-approved operation with a timeout is the right direction for multi-tenancy — what a tenant installs must be a recorded, revocable, expiring object rather than a config-file edit.
- [Hermes #110574: desktop connect runs on the connection operation and returns no sign-in link in the result](https://github.com/NousResearch/hermes-agent/pull/110574) — 6,964 core lines across 21 files, based on #110368's branch and flagged sweeper:risk-compatibility. On the desktop, connect now shows one card for all requested apps, waits until the user is done with it, and returns one outcome per app with no sign-in link in the result and no renderer polling. On CLI, TUI and messaging platforms the links still come back in the tool result all at once; PR3 (NS-869) changes that. Leaving the link in the tool result hands a clickable credential entry point to the model's context, so the separation is worth noting.
- [Hermes #110368: connector code spread over six flat files consolidates into one tools/connectors/ package](https://github.com/NousResearch/hermes-agent/pull/110368) — 789 core lines across 20 files, a pure move with no user-visible change, labelled P3. It is the middle step of the NS-867 to NS-868 chain: first make one `manage_connections` tool cover both managed connectors and local MCP servers, then consolidate the code into a package, then move managed connectors onto the connection operation. Notably the repo draws where the PR sits in that chain as a mermaid diagram in the description — a communication form worth copying for our own multi-PR refactors.
- [dsh #3874: description is required on bash/run_code, so a model that omits it has the whole tool call rejected](https://github.com/deepseek-ai/deepseek-harness/discussions/3874) — 7 upvotes, 6 comments. Tool calls are rejected with `invalid arguments: missing required property "description"`, and the proposal is to make `description` optional on bash and run_code. Since we do tool calling on DeepSeek ourselves, this is a schema-compatibility trap worth knowing in advance: marking an explanatory field required lets the model's phrasing habits decide whether a call succeeds. Dated 2026-08-21 and pulled into today's window by its score, not new.

## Security and compatibility

- [Hermes #110472: npm audit reports an unfixed HIGH as fixed at 40.10.6](https://github.com/NousResearch/hermes-agent/issues/110472) — `apps/desktop/package.json` pins electron at 40.10.2 on current main. Running `npm audit` against a clean install reports two Electron advisories with `fixAvailable: { name: 'electron', version: '40.10.6', isSemVerMajor: false }`. But per the GitHub advisory API, GHSA-9f4c-93c8-jc8g (HIGH, a sandboxed iframe bypassing the allow-popups restriction via the OpenURL navigation path) has a vulnerable range of `>= 40.0.0-alpha.1, < 41.10.3` and is first patched at 41.10.3, never backported to 40.x; GHSA-r4w5-6pfg-jxp5 (MEDIUM, ProtocolResponse.url reusing the default session cache) sits alongside it. The conclusion is hard: `npm audit`'s `fixAvailable` is not authoritative, and the advisory's own first-patched version has to be read directly.
- [OpenClaw #147528: malformed progress-card content can stall the Control UI main thread for seconds](https://github.com/openclaw/openclaw/pull/147528) — P1. The existing raw-content block regex restarts its closing-tag search for every unmatched opening tag; at the existing 140,000-character markdown limit, 17,500 unmatched tags deterministically reproduce the JavaScriptCore Yarr hot path, with `String.replace` burning seconds in the macOS Control UI. The fix replaces it with a bounded scanner that tokenizes candidate tags once and indexes compatible closing tags. This is the price of feeding model output straight into a regex: agent-produced content is untrusted input as far as the renderer is concerned, and regex complexity is a real denial-of-service surface.
- [OpenClaw #143587: requests bind to the selected profile at Gateway admission, so later account changes cannot move accepted work](https://github.com/openclaw/openclaw/pull/143587) — 4,762 core lines across 53 files. Native actions need an atomic selected-account precondition and truthful receipts when accepted work outlives a later account selection or connection change. Requests now bind to the intended profile at Gateway admission, new actions check the selected account, and accepted work stays with its original session and admission while the captured authority remains valid; revocation, cancellation and host retirement still prevent later effects, and callers receive either an explicit rejection or the original accepted-run receipt rather than a silent account switch. It is another solution to the family our judgment-irreversible-external-write-protocol and judgment-one-external-account-one-serial-lane cover.
- [OpenClaw #147647: session selection goes only to the requesting browser, and RPC/MCP callers now get UNAVAILABLE](https://github.com/openclaw/openclaw/pull/147647) — 785 core lines across 29 files, flagged merge-risk: compatibility. Previously, one person asking an agent to select a session changed the view on every connected dashboard. Navigation and layout commands now affect only the browser that requested the turn, and if that browser disconnects the tool asks the user to retry from the open Control UI rather than picking another recipient. The PR states that this intentionally replaces the legacy broadcast contract including the behaviour documented in v2026.9.4, and that standalone RPC or MCP callers without a captured browser target now receive `UNAVAILABLE` — worth checking in any automation wired to OpenClaw over MCP.
