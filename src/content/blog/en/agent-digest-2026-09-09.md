## TL;DR — Today's Overview

> Generation fencing becomes OpenClaw's default fix, and dsh breaks the byte-stable system prompt invariant

1. **OpenClaw #137381: sessions_yield cleanup made long transcripts briefly unavailable; now one writer-fenced suffix mutation plus generation rotation** P2 but labelled merge-risk: availability and compatibility, 6,036 core lines across 34 files, and with 304 comments the most discussed PR of the day. Trailing-entry cleanup used to delete and reinsert the whole SQLite transcript, so history and bounded context were invisible to the model while the projection rebuilt. It is now one exact, writer-fenced suffix mutation that rotates the transcript generation to invalidate stale cursors and repairs identity, active-branch, FTS, watermark, parent and leaf-control state in the same transaction; if the compare-and-swap loses a concurrent write race, both SQLite and the in-memory SessionManager back off (the PR body is truncated there). For us: compaction and pruning are writers too, and must pass the same writer check as an ordinary append. Delete-and-reinsert is not an atomic operation. — [source](https://github.com/openclaw/openclaw/pull/137381)

2. **Three OAuth refresh races in one day: OpenClaw fences shared credential generations (#141477 / #142628), Hermes keeps refresh_token when a response omits it (#62333)** #141477 (P1, 11,453 core lines across 71 files, merge-risk: compatibility): OAuth refresh ownership was process-local while the credential generation was shared, so a timed-out or failed owner could leave copied agents, queued writers, login persistence or rollback paths able to replay or restore an already-consumed refresh token; provider I/O and secret or config persistence crossed different ownership windows, so late settlement could overwrite a newer credential or resurrect an older one. The fix makes the SQLite auth-profile lifecycle the single owner. #142628 (P1) is the same family: Codex external auth waits only 10 seconds for the refresh callback, a rotation can complete after that timeout, and the next request then forced yet another refresh. It now records a secret-free access fingerprint plus the exact account ID after a successful login and reuses only a credential whose access bearer changed for that exact account. Hermes #62333 is title-only: do not drop the old refresh_token when a refresh response omits it. For us: a serial lane answers who is refreshing, not whether the world changed while the refresh ran. Single-use refresh tokens demand fencing by credential generation. — [source](https://github.com/openclaw/openclaw/pull/141477)

3. **OpenClaw's exec auto-reviewer goes from allow-or-ask to a three-way verdict and receives a bounded transcript with origin labels (#141987 / #142279)** #141987 (4,074 lines across 22 files) admits that under tools.exec.mode=auto the auto-reviewer was nearly useless in practice: its verdict was only allow or ask, ask meant a human approval card, any allow with non-low risk was converted to a human ask, and most commands never reached the model because the Gateway first demanded an enforceable plan (every executable resolved, paths pinned), so unquoted globs and chains with expansions skipped the model and went straight to a person. The reviewer can now allow, deny or escalate. #142279 (1,087 lines across 20 files) then gives it a bounded transcript: user, assistant, tool_call and tool_result entries with truncated text, tool name and an origin label (operator, channel, inter_session, internal_system, unknown), stressing that the label is derived from recorded user-turn provenance and never from role alone; the PR explicitly benchmarks against Codex's Guardian reviewer. For us: code-level gates remain the floor, but a model reviewer that sees the command without the intent and the origin is only a pre-filter for human approval. — [source](https://github.com/openclaw/openclaw/pull/141987)

4. **OpenClaw #141799 (impact:security, open): nested scope narrowing uses a literal membership filter and drops the read authority implied by operator.write** In-process synthetic-client scope narrowing (src/gateway/server-plugin-in-process-dispatch.ts:207-217) returns an empty list when the admitted scope set contains only operator.write and the nested request needs operator.read, while the canonical policy authorizeOperatorScopesForRequiredScope (method-scopes.ts:266-289) says write implies read and talk. The same policy was written twice and one copy ended up stricter than the other. It is a live sample of our judgment that gates must run the real consumer's code path rather than a hand-copied mirror list, and the direction (stricter, not looser) shows the problem with mirror lists is drift, not leniency. For our multi-tenant permission layer: scope implication must have exactly one implementation, and nested or delegated calls must call back into it instead of re-doing set arithmetic at the dispatch point. — [source](https://github.com/openclaw/openclaw/issues/141799)

5. **OpenClaw #141451 (P1): upgrades migrated databases and rewrote config before refusing to start, bricking the old package too; read-only admission now runs before the migration lease** Rated diamond lobster, reported by a user on X. The failure shape: a Gateway upgrade migrated databases and rewrote configuration, then discovered it could not start, by which time the previous package could no longer read the new data, so neither version booted. The fix runs read-only admission first (state and agent databases, legacy sessions and workspaces, Gateway readiness, the complete dry config-repair result), then takes the persistent migration lease and repeats the checks under it, allowing migration writes only if everything passes; direct server startup consumes the same snapshot. This is the third piece of yesterday's supersede candidate that doctor --fix has become rehearsal plus rollback: 2026.9.1 rolls back the npm candidate, 2026.9.3 rehearses in isolated candidate state, and now nothing is written until startability is proven. For schema migrations in our compose cluster: step one of a migration script should be a read-only proof that the new version can become ready on the current data, not an ALTER TABLE. — [source](https://github.com/openclaw/openclaw/pull/141451)

6. **dsh 0.1.5-alpha.1: dynamic system prompt updates without invalidating the KV cache (model must declare support), session format v2 to V3 in four days, plugin Agent and Inbox APIs changed again** Three items in the Sep 8 release notes change our knowledge base. First, 'dynamic system prompt updates without invalidating the KV cache, when the configured model explicitly declares support': our claim that all three harnesses treat a byte-stable system prompt as an invariant, and the dsh README line that any prompt change invalidates from the first affected token, no longer hold for dsh. Whether this is a model-side capability or the harness moving the system prompt into message history is unverified. Second, 'session format upgraded to V3: restoring a supported older session writes a new log and keeps the original, the system prompt is folded into message history, old PTC events and code preset references migrate automatically, custom log readers must adapt, and upgraded sessions cannot be read by older versions'; v2 was introduced on Sep 4. Third, 'ctx.agent removed, callers pass the Agent explicitly; Inbox becomes a type interface and hasPending and claim leave the public API; continuable subagents are no longer treated as root sessions for scheduling'. Also: bundled subagent runtimes move to Codex 0.153.4 and Claude Code 2.1.263, and fs-ext no longer needs native compilation on macOS and Linux. One fix deserves a note: the model could resume goals the user had paused. Pausing is a human decision the model must not be able to undo. — [source](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.1.5-alpha.1)

7. **Cloudflare Agents #2216: streams move to a 256 KB rollover block log, and the stream-to-session cutover becomes one transaction** 3,471 lines across 19 files. cf_agents_stream_chunks (one row per append) becomes cf_agents_stream_blocks: an append grows the open block row with an UPDATE until it reaches 256 KB, then opens the next; 'still one billed row per append, but a stream of thousands of chunks is a handful of rows, so deleting it is a handful of writes instead of thousands'. Schema v2 folds existing chunk rows into blocks on startup. Temporary stream blocks and the final session message live in the same Durable Object storage, and 'stream blocks, then session message, then delete the blocks' is a single transaction settled by writer.close({ commit, discard }) and error(reason, ...). This maps directly onto our claim that Durable Objects bill per written row and schemas must be designed by write count, and it is one more automatic startup migration queued ahead of 0.23. For us: if we ever stream through a Durable Object, the block is the row, not the chunk. — [source](https://github.com/cloudflare/agents/pull/2216)

8. **Claude Code 2.1.265 / 2.1.266: resumed subagents were breaking prompt cache, a 1 GB cap on tool results saved to disk, resume after a dead process keeps the interrupted tool call; 2.1.265 broke every request for proxy and gateway setups** 2.1.265 fixes two defects that directly affect subagent cost: resuming a foreground-spawned subagent changed its tool list and system prompt prefix, breaking prompt-cache reuse; and agent teammates and resumed subagents moved SubagentStart hook context and preloaded skills out of the prompt prefix on later turns, also breaking reuse. Our claim that fork inherits the prompt cache stands, but the resume path was leaking cache until 2.1.265. Same release: a 1 GB cap on tool results saved to disk with an in-conversation truncation notice; resume after the previous process died mid-tool no longer rewrites the last prompt and keeps the interrupted tool call marked interrupted (same direction as our rule that the tail of restored history must not be dropped); --plugin-dir can point at a folder of plugins with hot add and remove; a plugin path containing a backslash could bypass the symlink containment check. 2.1.266 is an emergency fix: in 2.1.265 the undocumented CLAUDE_CODE_USE_GATEWAY variable alone forced Cloud-gateway sign-in, so every proxy configuration using an API key, apiKeyHelper or custom auth headers failed every request with 'Not signed in to the Cloud gateway'. Anyone running Claude Code as a headless runtime behind a self-hosted gateway should skip that version. — [source](https://github.com/anthropics/claude-code/releases/tag/v2.1.265)

9. **OpenClaw #137576 (P1): input submitted during cloud workspace sync showed as interrupted after 15 seconds; queued input now stays admitted while the claim settles and re-reads the authoritative placement** 2,440 core lines across 24 files. The failure: a follow-up submitted while a healthy cloud workspace was reconciling waited 15 seconds, appeared interrupted and showed a red error, so users had to copy and resend; the same input loss hit initial worker setup, where a message accepted during sync became interrupted instead of starting once setup finished. The fix keeps the durable pending input admitted while the prior workspace-result claim settles, then re-reads the authoritative placement and continues the same run through the existing local, worker or redispatch path; initial setup joins only the exact live dispatch or recovery process. The placement and redispatch vocabulary in the PR body again shows OpenClaw's cloud workers already have a scheduling layer, more than our 'exec and filesystem only' description (flagged as a supersede candidate yesterday; this is the second piece of evidence). For us: 'accepted but the worker is not ready yet' is a state the task queue must persist, and a timeout must not demote it to a failure. — [source](https://github.com/openclaw/openclaw/pull/137576)

## The Pattern

The most reusable thing in today's 38 OpenClaw items is not a feature but a fix that surfaced in four unrelated modules at once: **give every mutable object a generation, compare-and-swap before writing, and abandon the whole write if you lose**. #137381 turns long-session cleanup from 'delete the whole transcript and reinsert' into one writer-fenced suffix mutation that rotates the transcript generation to invalidate stale cursors. #141477 moves OAuth refresh ownership from process-local to a shared credential generation, so a timed-out refresher can no longer replay a consumed refresh token. #129186 and #129535 bind voice-delegation callbacks to the tuple of session, requester, run and lifecycle generation, rejecting stale callbacks before any provider output. #137576 keeps queued input admitted while a workspace claim settles, then re-reads the authoritative placement and continues the same run. For a Postgres plus task-queue cluster like ours the implication is plain: a lease answers who is running, not whether this write is based on the latest state. The second question needs a generation column and an UPDATE with a WHERE clause. OpenClaw needed months of incidents to spread that to every write point; we can make it the default from day one.

The second signal is a change in the shape of gates. #141987 concedes that the exec auto-reviewer was 'nearly useless in practice': it could only allow or ask, and most commands never reached the model because no enforceable plan could be built for them. #142279 then hands it a bounded transcript in which every entry carries an origin label 'derived from recorded provenance, never from role alone'. That does not displace code-level evidence gates, but it adds a lesson: a model reviewer that sees the command without intent and origin is only a pre-filter for human approval. #141799 confirms the same point from the other side: one scope-implication policy was written twice, the literal filter ended up stricter than the canonical one, and the problem with mirror lists is drift, not leniency.

The third signal comes from dsh. 0.1.5-alpha.1 announces 'dynamic system prompt updates without invalidating the KV cache', conditional on the model declaring support, while the session format jumps from v2 to V3 in four days. Our knowledge-base line that all three harnesses treat a byte-stable system prompt as an invariant must become 'Hermes and OpenClaw still do; dsh has made it a model capability flag', and dsh's breaking-change count keeps climbing.

## Frameworks

What is displayed and what is routed must come from one projection; the same applies to our per-tenant model selection.

One loader needing two defaults for internal and public surfaces is a classic plugin-SDK compatibility trap.

- [Three title-only Hermes agent fixes: background review memory access scoped to its trigger, empty parent tools list inherited and frozen for cache parity, a surface switch must not re-prefill the whole request](https://github.com/NousResearch/hermes-agent/pull/103579) — #105921, #103579 and #104414 have no body; details unverified. ## Clusters and reliability

- [OpenClaw #142135: a Gateway deadline ended the turn before any reply without a durable notice, so reloaded history showed consecutive user requests with no explanation](https://github.com/openclaw/openclaw/pull/142135) — 1,092 lines across 19 files, fixes #141839. Both terminal phases now use the existing failure-report writer to persist a notice that the turn ended before a reply, preserved through history pages, cursor updates, reset navigation and archives, with exact current ownership rechecked at commit. Same topic as our rule that an unanswered trailing user message must not be dropped, plus one addition: the absence of a reply must itself be recorded.
- [OpenClaw #142991: an accepted image_generate job could lose its plugin resources after returning started; ownership now lives as long as the job and its cleanup](https://github.com/openclaw/openclaw/pull/142991) — 2,329 lines across 15 files. A retired source cannot admit new tasks, but an already accepted task retains its captured providers until work and cleanup finish. The same rule as last week's #139657 (no release of ownership without cleanup evidence), applied in another module.
- [OpenClaw #142278: when an embedded run ends on a timeout or idle-timeout breaker, the model fallback chain stopped without saying why](https://github.com/openclaw/openclaw/pull/142278) — Closes #141838. Terminal results are intentionally not eligible for another model attempt, but no diagnostic explained the stop; each terminal producer now carries a bounded cause to the existing fallback observer, recorded once per multi-candidate chain. Our own model fallback (primary DeepSeek plus backup) should also distinguish retryable failures from terminal ones and log the latter.
- [OpenClaw #129186 / #129535 (both P1): voice delegation bound to session, requester, run and lifecycle generation, stale callbacks rejected before provider output; yielded subagent results return to voice](https://github.com/openclaw/openclaw/pull/129186) — #129186 (2,674 lines across 18 files): a new spoken delegation could start competing embedded work or deliver a late result after the authoritative Talk owner had been cancelled, replaced or revoked; it now keeps one canonical parent run, steers newer requests into its exact backend, and delivers completion or failure under a one-shot claim. #129535 (1,516 lines across 19 files): delegated results previously returned only to chat, not voice, and retained callbacks could outlive a replaced owner. A fourth shape of our 'completion announcement to the wrong session' record: not the wrong recipient, but an owner that no longer exists.
- [Hermes #102574: periodic scheduler callbacks isolated from blocking siblings](https://github.com/NousResearch/hermes-agent/pull/102574) — Title only, no body, unverified. - [Hermes #101420: a cross-OS install and update E2E matrix, 41 install-to-update combinations, run every 12 hours](https://github.com/NousResearch/hermes-agent/pull/101420) — 18 Windows, 15 macOS and 8 Linux combinations, installed the way users actually do (Setup.exe via GUI automation, dmg, installer scripts) and then updated through every supported path, asserting on installed checkout sha, update-marker lifecycle and app relaunch. - [OpenClaw #141107: managed Responses proxies did not receive the requested session-affinity header, and Azure-compatible routes lost session and cache-retention values](https://github.com/openclaw/openclaw/pull/141107) — Fixes #140918.
