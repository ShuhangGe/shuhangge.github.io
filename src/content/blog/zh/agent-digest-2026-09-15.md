## TL;DR — 今日概览

> 守卫装错了位置：脱敏不管落库、denylist 只守读、spawn 悄悄收紧

1. **Hermes：脱敏不覆盖持久化，粘进聊天的凭证原样落进 state.db 和 FTS5 镜像表** 即便 `security.redact_secrets: true`，脱敏今天只作用于终端输出、日志、显示与 `debug share` 四个出口，不作用于写库：`hermes_state_messages.py` 的 `append_message` 在当前 main（ee44529）上按「as sent except lone surrogates」原样存行。结果是一次粘贴（例如从 BotFather 拿到的 Telegram bot token）同时出现在 user message `content`、后续每一条用到它的 assistant `tool_calls`、`reasoning` / `reasoning_content`，以及镜像这些列的 FTS5 content 表——四份副本。下游 `hermes backup` 与不带 `--redact` 的 `hermes sessions export` 把它们一起搬走。我们为证据闸门保留 model-visible / logged 全量会话日志，这条正好打在同一个位置：脱敏必须是写库函数的一部分，且全文检索表要单独算一份副本。 — [来源](https://github.com/NousResearch/hermes-agent/issues/110416)

2. **OpenClaw 2026.9.4：sessions_spawn 用调用方的工具面当子 agent 天花板，无 changelog 无迁移** 2026.9.4 起，解析 `sessions_spawn` 子 agent 的工具时会把「派生会话已解析的工具列表」作为继承 allowlist（caller tool-policy ceiling）叠加上去。于是一个 `agents.entries.*.tools.allow` 里显式写了 `read, write, edit, apply_patch, exec, process` 的 coding worker，只要它的父会话自身工具面没有 `group:fs` / `group:runtime`，就再也起不来，报 `No callable tools remain after resolving explicit tool allowlist (...; inherited tools.allow: ...)`。这恰好废掉一个常见拓扑：消息/PA 主 agent 跑 Claude CLI runtime，文件与 exec 都在 CLI harness 里做，所以它在 OpenClaw 侧的工具面本来就是空的。同一份配置在 2026.9.3 上能跑；issue 标 P1 + impact:security + needs-live-repro，仍 open。 — [来源](https://github.com/openclaw/openclaw/issues/147857)

3. **Hermes：敏感路径守卫只挂在 4 个 fs reader 里的 2 个，fs_read_text 把 auth.json 返给仪表盘** `_is_sensitive_path` 在 #57505 里被明确写成 list / read / download 的读侧守卫，但实现上只有 `fs_read_data_url` 与 `fs_download` 调用它。于是 `fs_read_text` 把 `.env`、`auth.json`、`mcp-tokens/*` 的内容直接返给一个已认证的仪表盘会话，`fs_list` 还负责把它们枚举出来。修法（#110513，35 核心行）是把检查挪进 `_fs_regular_file`——每个 fs reader 都必经的那个解析器——并删掉两份 per-handler 拷贝，`fs_list` 用同一个谓词过滤。这是我们 judgment-gates-bind-to-real-consumption-point 的一个外部活例：守卫写对了、文档写对了，只是没挂在公共路径上。 — [来源](https://github.com/NousResearch/hermes-agent/pull/110513)

4. **Hermes：写 denylist 从读 denylist 漂移，write_file 能覆盖 vault.key 与 webhook HMAC 密钥** `is_read_denied` 拒绝 8 类 HERMES_HOME 存储（`auth.json`/`auth.lock`、`webhook_subscriptions.json`、`auth/google_oauth.json`、`cache/bws_cache.json`、`vault/`、`browser-profile/`、`.env`、`.anthropic_oauth.json`），而 `is_write_denied` 只拒其中 3 类。于是 agent 的 `write_file` / `patch` 可以覆盖 auth token、webhook HMAC secret、Google OAuth、Bitwarden 明文缓存、`vault/vault.key` 与浏览器 cookie。报告者把 `HERMES_HOME` 指到临时 profile 在当前 main 上复现。两份手维护的镜像清单必然漂移——这条应当直接写进我们的闸门规则：读与写共用一个谓词，不存在「记得同步」的清单。 — [来源](https://github.com/NousResearch/hermes-agent/issues/110464)

5. **Hermes v0.21.3：state.db 句柄所有权收口，读者改只读、进程内写者共用注册表句柄** 这个 tag 把 v0.21.2 以来约 338 个 PR 打包发给下游（Docker 镜像、Hermes Cloud、托管部署，Cloud agent 自动追最新 release tag）。两处值得抄：#110934（fixes #100896、#103339）让网关、仪表盘/Desktop 后端、ACP 与 CLI 的读者以只读方式 attach，进程内写者共用注册表句柄，于是健康拓扑下不再触发 `N live SessionDB handles` 前兆；#110061（fixes #55712）把网关两条 refresh 路径（cookie 门与 Desktop 原生 bearer 路由）里携带同一个轮换 refresh token 的并发请求合并，Desktop 唤醒突发不再把已轮换的 token 重放进 Portal 的 reuse detection 从而吊销整个会话，且 refresh 移出事件循环，慢 IdP 不再冻住 `/api/status`。对应 Portal 侧 hermes-portal#1209（30 天滑动空闲窗口、5 分钟轮换宽限）。 — [来源](https://github.com/NousResearch/hermes-agent/releases/tag/v2026.9.14)

6. **OpenClaw：同一个已认证管理员会话，授权范围随模型路由变（Claude CLI/MCP vs OpenAI）** 报告称在一个已认证的 Control UI 管理员会话里，走 Claude CLI/MCP 路由拿到的是 caller-scoped 的 automation 访问，把同一个会话切到 OpenAI 路由则返回 Gateway-wide 访问。issue 自己标注 `NOT_ENOUGH_INFO`——当前 upstream main 上还没有确定性复现，Claude 侧的原始工具响应也未独立重抓，所以数字待核实；但它要求维护者分诊并拉安全 owner 进来（P2 + impact:security + needs-security-review）。即便最后证伪，这个问法对我们也是硬要求：授权范围不能是模型路由的函数，租户边界必须在进入 provider 适配器之前就固化。 — [来源](https://github.com/openclaw/openclaw/issues/147614)

7. **Claude Code v2.1.271：按命令粒度的出站域白名单、子 agent 可关 CLAUDE.md、计费倍率到 10x** 三处与我们直接相关。① sandbox auto 模式下 Bash / PowerShell / Monitor 支持 per-command `allowed_domains`：一条命令需要的主机随这条命令一起被审，且只为它打开，其它主机拒绝——这是比「每沙箱一张白名单」更细一档的出站控制粒度。② agent frontmatter 与 `--agents` JSON 新增 `omitClaudeMd`，自定义与插件子 agent 可以不加载 user / project / local CLAUDE.md，但受管策略文件仍然加载——「策略必加载、用户上下文可关」这个二分正是多租户要的形状。③ `modelPricing` 受管设置与 Claude apps 网关 `pricing` 块支持大于 1 最高 10 的 `multiplier`，用于内部加价计费。另有 `claude self-hosted-runner --drain-marker-file`（SIGTERM 时按 host drain 上报，仅遥测）与 `claude plugin install/update --accept-command`（精确接受上次 `--json` 展示的那条命令，替代无差别 `-y`）。 — [来源](https://github.com/anthropics/claude-code/releases/tag/v2.1.271)

8. **Hermes：工具的可见性和工具的授权来自两个不同数据源，于是模型每次调用都吃 404** 一个付费的 Hermes Cloud 账号（v0.21.2）调 `manage_connections(status)` 得到 `tool gateway request failed with status 404`，然后模型把用户指向一个同样 404 的 Portal Connectors 页面。根因不是网关：网关对任何没有被 Portal 开通 connectors 的账号返 404，这是设计。问题是 Hermes 用 `paid_access` 或一个实时 free tool pool 决定要不要把这个工具展示给模型，而这两者都不表达「connectors 是否已开通」。修法（#111238，88 核心行）让未开通的账号根本看不到 `manage_connections`。对多租户是一条硬规则：模型看到的工具清单必须由那个最终会准入调用的授权源派生，否则每个未开通租户都得到一个模型可见的死路，而模型会自己编一条恢复路径出来。 — [来源](https://github.com/NousResearch/hermes-agent/pull/111238)

9. **OpenClaw #147276：Docker 里的 Gateway 经宿主 socket 起兄弟沙箱容器，受管挂载必须 bind-backed** 这是我们的形态：Gateway 跑在容器里，用宿主 Docker socket 起兄弟沙箱容器。缺陷是沙箱里看不到 workspace 文件与物化的 skill。修法让 shell 与 browser 的受管挂载解析到与 Gateway 文件工具同一份 bind-backed 的 workspace / agent / skill 文件，只读挂载保持只读；受管来源**必须**是 bind-backed，volume / tmpfs 布局现在报可执行的错误而不是静默半工作；已保留的沙箱如果挂载不同必须按提示的命令重建，改 Docker 挂载或连接后要重启 Gateway。默认 Compose 桥上的 Browser CDP 连通性仍是已知限制。P1，merge-risk 标 compatibility。 — [来源](https://github.com/openclaw/openclaw/pull/147276)

10. **cloudflare/agents #2244：清理记账行失败会把一次成功的 run 变成失败返回** `runFiber` 在收尾时删掉 `cf_agents_runs` 里那条已完成的 legacy 记账行。删除失败时，这个 `SqlError` 取代了 fiber body 的真实结果向调用方抛出——body 明明返回了 `completed`，RPC 却以「模拟的 fiber 清理失败」reject。修法把删除降级为 best-effort：记日志、把行留给既有的 recovery pass，不替换结果。回归测试用真实 SQLite trigger 只让最后那次 `cf_agents_runs` delete 失败来证明。虽然只有 66 行 / 3 文件，但这是我们队列里同型 bug 的教科书样本：任何「先记结果、再清理」的序列，清理的失败都不能成为这次操作的结果，否则调用方按错误重试会把已完成的工作再跑一遍。 — [来源](https://github.com/cloudflare/agents/pull/2244)

## 本期主轴

## 守卫的位置比守卫的内容重要

Hermes 一天之内交出三份同型证据。

**脱敏不覆盖落库。** `security.redact_secrets: true` 管终端输出、日志、显示与 `debug share`，不管持久化——`append_message` 在当前 main 上按「as sent except lone surrogates」原样写行，于是粘进来的一个 token 同时落在 `content`、后续每条 `tool_calls`、`reasoning_content`，以及镜像这三列的 FTS5 content 表里：一次粘贴四份副本，再被 `hermes backup` 和不带 `--redact` 的 export 一起搬走（#110416）。

**守卫只挂在两个入口。** `_is_sensitive_path` 自我声明是 list / read / download 的读侧守卫，实际只有 `fs_read_data_url` 与 `fs_download` 调它；`fs_read_text` 把 `.env`、`auth.json`、`mcp-tokens/*` 返给已认证的仪表盘会话，`fs_list` 负责枚举。修法是挪进每个 reader 必经的 `_fs_regular_file`（#110513）。

**两份清单漂移。** `is_read_denied` 拒 8 类存储，`is_write_denied` 只拒 3 类，`write_file` / `patch` 因此能覆盖 `vault/vault.key`、webhook HMAC secret 与浏览器 cookie（#110464）。

三处的策略本身都没写错，错的是它挂在哪条路径上。`@shared/judgment-gates-bind-to-real-consumption-point`（asserted_at 2026-09-08）讲的是自检要绑真实消费点、镜像清单有毒；今天的证据把同一条规则从「检查」推到「守卫」本身——守卫要挂在所有消费者共用的那个解析器上，读与写共用同一个谓词。

OpenClaw 同日从另一端补上配套教训：2026.9.4 把调用方会话已解析的工具列表当作子 agent 的继承 allowlist，于是消息/PA 主 agent（Claude CLI runtime，自身工具面没有 `group:fs` / `group:runtime`）派给 coding worker 的每次 spawn 都以 `No callable tools remain after resolving explicit tool allowlist` 失败；同一份配置在 2026.9.3 上能跑，无 changelog 也无 doctor 迁移（#147857，P1，impact:security）。这条正打在 OpenClaw 自己 VISION.md 的「改 schema 必须同时提供 `doctor --fix`」规则上——收紧授权面被当成了 bug fix，而不是 schema 变更。

落到我们身上三条：① 脱敏放进写库函数，全文检索表算一份独立副本；② 读与写的敏感路径判定共用一个谓词，撤掉任一处都要能让测试转红；③ 子 agent 的工具授权 = 子 agent 声明 ∩ 租户策略，不从调用方的工具面继承；真要收紧，同一个 PR 里必须带存量拓扑的启动测试。

## 框架动态

- [OpenClaw #147994：同一个模型可以按 harness 分成多行出现在选择器里](https://github.com/openclaw/openclaw/pull/147994) — 5,371 核心行 / 66 文件。运营方可以给一个确切的 model 条目加 `pickerRuntimes`，同名模型按 harness 标签分行展示，新老会话都能选；配置的默认值不变，选 Default 会清掉会话级选择（runtime 拥有的会话保留自己的锁）。Gateway 保持一个 canonical model，另外单独发布经过校验的 runtime 选项。
- [OpenClaw #147571：子 agent 的「在等什么」变成可观测状态，执行与结果投递分开](https://github.com/openclaw/openclaw/pull/147571) — 6,705 核心行 / 42 文件。此前父 agent 和运营方分不清一个子 agent 是在执行、在等另一个子、在等输入、还是已完成但结果还在投递中；模糊的 yield 与取消竞态会让活儿搁浅或让父 agent 提前回话。现在子 agent 工具与 Control UI inspector 会说明每个子在等什么，支持按任务等待与显式 notify / steer / followup，cron 跟随后代结算，TaskFlow/Lobster 恢复自己拥有的 checkpoint。
- [OpenClaw #148261：为「压缩持久化原子化」铺路的内部重构](https://github.com/openclaw/openclaw/pull/148261) — 647 核心行 / 14 文件，公开 SessionManager 签名与 SQLite 存储契约都不变。目标是让压缩记账拥有一个可以搬进既有 worker owner、且事务期间不回调活的 SessionManager 对象的存储操作：边界与记账在原始 writer authority 下一起提交，之后再采纳已提交的 parent/version 事实。这是我们 judgment-compaction-is-most-reworked-component 的又一次月度验证——压缩的返工这次落在所有权而不是算法上。
- [OpenClaw #147421：Bun 用占位实现替换 ws 与 undici，插件网络全线出问题](https://github.com/openclaw/openclaw/pull/147421) — 在 Bun 下运行时，Bun 为 `ws` 与 `undici` 提供的部分 package-entry 实现会让 Browser relay、Mattermost、Slack relay 与 API 代理、Reef、Codex inference、Nextcloud Talk、Crabbox 卡住、忽略 proxy 选项或启动失败。修法是把既有的 gateway-client npm-`ws` 加载器发布成带类型的 `openclaw/plugin-sdk/websocket-runtime` 契约，Slack 改用共享的 HTTP/1 环境代理 dispatcher。换运行时不是零成本的，这条值得记在选型账上。
- [OpenClaw #142545：记忆 dreaming 晋升会写出超过 bootstrap 上限的文件](https://github.com/openclaw/openclaw/pull/142545) — Memory Core 的晋升此前用 10,000 字符的 writer 默认值，哪怕消费它的 agent 只注入更少的 `MEMORY.md`；其 append 回退路径于是可能提交一个超限文件并把候选标成已晋升。现在 writer 预算取共享同一 canonical workspace 的 agent 中最小的那个 per-file bootstrap 上限，用户书写与歧义内容无条件保留，机器生成条目的删除由 `maxPriorEntryLossFraction`（默认 25%）兜底，文件与晋升状态一起提交。
- [Hermes #111038：Windows 上的 llama-server 用 job object 绑住，孤儿进程改成显式回收](https://github.com/NousResearch/hermes-agent/pull/111038) — 1,137 核心行，fixes #110561。每个 Windows router 先挂起启动，分配到一个专用、不可继承的 `KILL_ON_JOB_CLOSE` job，再 resume；两个 breakaway 标志都不开，setup 失败会清掉挂起的子进程与句柄。job 保留到 supervisor 生命周期结束，stop / crash-restart 时关闭，因此 restart backoff 期间的 stop 不会把 server 复活。旧的孤儿进程改成一个带身份校验的显式「Turn off」动作，记录 router/owner 创建时间与可执行文件身份。

## 集群与可靠性

- [OpenClaw #148508：执行期限属于 run 的所有者，重复计时器一律删掉](https://github.com/openclaw/openclaw/pull/148508) — 1,330 核心行 / 25 文件，P1。长任务此前会被更短的启动、监控或等待超时截断，恢复后丢掉已配置的预算，或丢掉迟到的回复。现在 ACP turn 与已批准的命令续跑保住自己的执行预算，恢复与重启的子 agent 保留保存的 timeout（包括显式的 0），后台复审用普通 agent 预算；补丁直接删掉 ACPX 自己那份重复的 turn timer。这与我们 fact-hermes-unified-deadline-primitive 记的是同一条结论，现在在第二个代码库里被独立得出。
- [OpenClaw #147499：sessions_yield 之后父 agent 的授权丢了，自动化管理报「找不到」](https://github.com/openclaw/openclaw/pull/147499) — 一个已认证的 Control UI 管理员用 `sessions_yield` 等子 agent 之后，继续管理已有 automation 会报 `Automation not found`。原因是 yield 关掉了原来的 run，子 agent 结算又开了一个合成的续跑；现在注册表把校验过的父授权通过已提交的 child batch 传递，Gateway 准入再为后继 run 发只含管理权限的新 grant。取消、会话 reset/archive、新的直接用户回合与 Gateway 重启仍然撤销这个 handoff。异步边界会吃掉授权——这是每个做 yield/resume 的编排层都要过的一关。
- [OpenClaw #147887：会话投递队列的 SQLite 从 Gateway 线程搬进共享状态 worker](https://github.com/openclaw/openclaw/pull/147887) — 3,552 核心行 / 19 文件。此前会话投递队列 API 返回 Promise 却在 Gateway 线程上执行 SQLite，包括重试调度与重启恢复期间。迁移保留去重、重试记账、结算与重启恢复，无配置 / schema / 保留数据迁移；生产者、恢复、生成媒体准备与调度器在一次操作里带同一个已捕获的数据库上下文，调度器关停时先 join 已准入的读并 drain，再关库。这是昨天那批「把 SQLite 挪出 Gateway 事件循环」的续集。
- [OpenClaw #148032：恢复操作不再解码每一条无关的会话](https://github.com/openclaw/openclaw/pull/148032) — 主会话恢复的校验、释放与预留转换此前会读并解码全部保留会话，哪怕权威的租约或预留还在它已知的 key 上——大体量的无关会话负载于是在例行恢复里烧 gateway 主线程 CPU。现在恢复所有者先按已知 key 选，只有身份对不上时才回落到既有的 inventory 搜索。PR 自己声明测量来自受控 fixture，生产延迟未测。
- [OpenClaw #148099：Auto 会话在配对设备间分摊，但这是偏好不是槽位预留](https://github.com/openclaw/openclaw/pull/148099) — 突发期间 Auto 会把活儿全堆到一台配对设备上，再在容量变化时失败，而其它主机还有余量。现在选择器会把 Gateway 已准入的活计入考量，让新会话在 worker 槽位遥测追上之前就散开；在准备 workspace 之前变得不合格的设备，可以在其失败分配被清理后替换。PR 明确写清这是**放置偏好而非原子槽位预留**，节点仍按当前容量逐个准入真实 worker 启动——这句话本身就是一条可抄的接口说明写法。
- [OpenClaw #145940：重启把已完成的子 agent 任务重写一遍，flow revision 每次都涨](https://github.com/openclaw/openclaw/pull/145940) — Gateway 每次重启都会重写已结束的子 agent 任务并抬高其 flow revision，尽管没有任何新活。修法让任务注册表跳过等价的终态写入，镜像的 flow 在写之前先比对派生状态，过期的 flow 仍会修复，失败的任务通知仍可重试。PR 带三次真实 Gateway 启动的对照表：修复前 revision 3 → 4 → 5，修复后 5 → 5 → 5。空转重启不该产生状态变更——这条对我们的幂等恢复是直接可抄的验收形式。
- [OpenClaw #147871：主动停止被报成 SIGTERM 失败，子 agent 在 yield 前丢掉后台结果](https://github.com/openclaw/openclaw/pull/147871) — 在把活儿交给子进程之前停掉一个后台命令，会在聊天里产生一个假的 SIGTERM 失败；一个在等自己后台命令的子 agent 也可能在没有任何完成唤醒的情况下 yield，把任务停在原地，而它的 CI watcher 还在为过期的 proxy 访问重试。现在进程所有者显式记录停止请求并与结算结果比对，确认过的停止只留在工具详情里、不再变成聊天失败；子 agent 在 yield 前先收集后台结果，CI watcher 对 proxy 认证拒绝立刻上报。
- [OpenClaw #139878：多 agent 库的启动预检改成有界并行（并发 2）](https://github.com/openclaw/openclaw/pull/139878) — Gateway 启动时逐个检查 agent 数据库，在 agent 很多的安装上拖长启动与更新重启等待。现在预检所有者在「合格 schema 子读者」与「保留的私有快照」两条路径上都 await 一个并发 2 的池，保留 schema 与所有权校验、去重、busy timeout 与按输入顺序返回结果。代价写在 PR 里：两份 fallback 快照可以并存，峰值临时存储与 I/O 高于串行。merge-risk 标 availability。

## 对我们知识库的影响

- 需重审 **Hermes Agent 架构：单租户个人 agent、单 SQLite 多进程共写、system prompt 字节稳定不变量**: 「单 SQLite `state.db` 多进程共写：CLI / 网关 / cron / TUI / API server 五类进程共写一个 WAL + FTS5 库」。这句在 v0.21.3（v2026.9.14，2026-09-14）之后不再准确。#110934（fixes #100896、#103339；salvage #107974）把句柄所有权收口：网关、仪表盘 / Desktop 后端、ACP 与 CLI 的**读者以只读方式 attach**，**进程内的写者共用注册表句柄**，于是健康拓扑下 `N live SessionDB handles` 这个前兆不再触发。换言之「五类进程共写」现在应改写为「写者集合被收窄并共用句柄，读者只读」。同一 tag 还改了另一处我们记过的结构：#110061（fixes #55712）把网关两条 refresh 路径上携带同一轮换 refresh token 的并发请求合并，并把 refresh 移出事件循环。条目的 asserted_at 是 2026-09-08 / v0.21.1 / commit 8aa219e，本 tag 之后版本基线也该更新；热更新期间新旧进程并存导致 WAL 损坏（#23717）是否仍然成立需要按新句柄模型重新核对——open_questions 里那条压测计划应当在 v0.21.3 上重跑。 ([证据](https://github.com/NousResearch/hermes-agent/releases/tag/v2026.9.14))
- 需重审 **各家子 agent 的深度与并发边界值（2026-09）**: 表格里 OpenClaw 那一行：「`sessions_spawn`，`contextMode` isolated / fork；Swarm 递归 spawn 与跨会话可见默认开（#136755）；走全局 lane `maxConcurrent`，默认 `min(16, max(8, CPU))`」——这一行基线停在 2026.9.2，缺了 2026.9.4 新增的**第三个维度**：工具授权。#147857（P1、impact:security、open）报告 2026.9.4 起解析子 agent 工具时会把**调用方会话已解析的工具列表**作为继承 allowlist 叠加（caller tool-policy ceiling），于是子 agent 的 `agents.entries.*.tools.allow` 即便显式写了 `read, write, edit, apply_patch, exec, process`，只要父会话自身工具面缺 `group:fs` / `group:runtime` 就一个都拿不到，spawn 直接失败于 `No callable tools remain after resolving explicit tool allowlist (...; inherited tools.allow: ...)`；同一份配置在 2026.9.3 上可用。条目这一行应从「深度 / 并发」两列扩成三列：**深度、并发、子 agent 可获得的工具集**，并注明 OpenClaw 的第三列现在是「子 agent 声明 ∩ 调用方已解析工具面」。需要注意 issue 带 `clawsweeper:needs-live-repro` 标签，官方尚未确认，具体错误串与触发条件待核实。 ([证据](https://github.com/openclaw/openclaw/issues/147857))
- 需重审 **Hermes 跨 profile 凭证泄漏模式与供应链钉版**: 「Hermes 多 profile 用 contextvars 隔离 secret；scoped miss 回落 os.environ 曾导致跨 profile 凭证泄漏」，以及正文里那条「终端持久 shell 的 `export -p` 快照把 `.env` 秘密明文写进 /tmp 缓存（#48441）」。条目把 Hermes 的 secret 问题归纳成两类：**作用域回落**与**临时文件快照**，缺了第三类也是最大的一类——**主存储本身**。#110416（type/security、open、P3）：即便 `security.redact_secrets: true`，脱敏今天只覆盖终端输出、日志、显示与 `debug share`，**不覆盖持久化**；当前 main（ee44529）的 `hermes_state_messages.py::append_message` 按「as sent except lone surrogates」原样写行，于是一个粘进聊天的凭证同时出现在 user message `content`、后续每一条用到它的 assistant `tool_calls`、`reasoning` / `reasoning_content`，以及镜像这些列的 FTS5 content 表；`hermes backup` 与不带 `--redact` 的 `hermes sessions export` 把它们一起带走。条目应补一句可迁移规则：脱敏的绑定点是写库函数，不是任何展示或导出路径；全文检索 / 向量索引这类派生表要各算一份独立副本单独处理。另需并入 #110464（读 denylist 8 类、写 denylist 3 类，`write_file` 可覆盖 `vault/vault.key` 与 webhook HMAC secret，在当前 main 复现）：Hermes 的凭证问题不只是「读得到」，还有「写得进」。 ([证据](https://github.com/NousResearch/hermes-agent/issues/110416))
