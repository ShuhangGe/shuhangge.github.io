3. **Cloudflare Agents #2219 / #2223 / #2226：一轮 Think 曾读整份 transcript 2 + T 次，400 条消息 + 20 次工具更新约 10k 次计费行读对 30 次行写** #2219（核心路径 1,744 行 / 7 文件）PR 正文给了少见的生产级数字：一轮长 Think 会读整份持久化历史 2 + T 次，T 是本轮工具更新数（客户端结果、审批、服务端工具跨消息结果、执行结果），每次读走 sized path 查询（字节子查询每条消息数行计费）再 hydrate 每一行；400 条消息的 transcript 加 20 次工具更新，量级是 10k 次计费行读，而这一轮的流日志只写约 30 行。修法全在读侧：工具更新从内存解析目标行，不再调 session.getHistory()。#2223：恢复进度标记改从流日志派生，去掉每个 credited chunk 一次 DO KV get + put（每工具调用两次、每段文本开始一次、每 5 秒一次）。#2226：auto-compaction 阈值检查曾在每次插入后跑 sized path CTE，成本随 transcript 增长，现在内存里维护 token 总数并按增量修正。昨天我们把「按写行数设计 schema」列为新条目，今天的证据说另一半更大：DO 按行读写都计费，而读放大是隐性的、随会话长度线性增长。对我们：任何「每轮重读整段历史」的编排都要先算读账单，不管底层是 DO 还是 Postgres。 — [来源](https://github.com/cloudflare/agents/pull/2219)

4. **OpenClaw #133693（P1，diamond lobster）：generation 围栏的反面，隔离 cron 因「prepared runtime generation 已被取代」在模型执行前失败，现在租约钉住采样时的 generation** 昨天的主轴是「给每个可变对象配 generation，写前 compare-and-swap」。今天这条是同一机制的失效面：Gateway 在异步 cron 准备期间重新发布某个 agent 的 prepared runtime，cron 到执行时发现 generation 已变，直接以 prepared model runtime plugin generation was superseded 失败。修法不是放松围栏，而是把校验前移：cron 先采样已发布的 reply-dispatch generation，校验 owner 身份、配置与插件元数据身份，然后在 auth / session 持久化能发布替代版本之前拿到一个钉在该 generation 上的租约，整个嵌入执行期间只用这一个 generation；后来的发布不再把已准入的 run 拽到 generation B，也不会出现「A 的选择事实 + B 的执行」。同日 #137147 补了时间维度：node.invoke 的超时曾随 Gateway 墙钟移动而提前或滞后到期，跨 owner 传递剩余时长时不足 1 ms 的正余数会归一成「无上限的零」，现在整条链路只带一个按 elapsed 时间计的 deadline，只有发给 node 的超时值向上取整。对我们：租约要同时钉住「谁」和「哪个 generation」，而且 deadline 用单调时钟，这两条都是任务队列里的默认设置。 — [来源](https://github.com/openclaw/openclaw/pull/133693)

## 本期主轴

今天最强的信号来自 DeepSeek 这一侧，而且直接改我们的成本模型。dsh 0.1.5-rc.1 把 **DeepSeek-V41-Flash** 设为新会话默认，发布说明用一句话把它和昨天的谜团接上：该模型「支持文本、图片及会话历史中的系统提示词更新」。所以「动态修改系统提示词且不破坏 KV Cache」不是 harness 把 system prompt 搬到别处的技巧，而是模型在会话历史里接受一条 system 消息、并把它当普通前缀延续来缓存。知识库里「三家 harness 都把 system prompt 字节稳定当不变量」和「任何 prompt 变化都从首个受影响 token 起失效」这两条，从今天起要按模型分叉：V4 Pro 与 Hermes / OpenClaw 仍是老规则，V4.1 Flash 走新规则。对我们的生产 agent，值得立刻做一个实验：同一段对话中途换 system prompt，对比 V4 Flash 与 V4.1 Flash 的 prompt_cache_hit_tokens。同一天 DeepSeek API 站发了 news260910，标题不透明，价格是否随新模型变化待核实。

第二个信号是 OpenClaw 的云 worker 一天五个 PR 长成了调度器：预备镜像复用、有界热备池、按需 prepare RPC、跨 Gateway 升级保活、机器规格投影。#143372 的一句话可以直接抄进我们的设计文档：「分配与 placement 原子完成，每个已登记 node 只能被消费一次，补池不超过容量上限，过期、重启、清理失败都保留所有权直到 provider 删除被确认」。这和我们的多租户集群是同一个问题，而 OpenClaw 用 8,141 行核心代码回答了它。「cloud workers 只外派 exec / fs」这条断言三天内被三批证据推翻，该走 supersede 了。

第三个信号是两份「隐藏账单」。Cloudflare Agents #2219 给出生产量级：一轮 Think 读整份 transcript 2 + T 次，400 条消息 + 20 次工具更新约 10k 次计费行读对 30 次行写，昨天我们只算了写。OpenClaw #133693 则是昨天「generation 围栏」主轴的反面：围栏太严会把合法的在途工作杀掉，修法是租约钉住采样时的 generation，而不是执行时再校验。两条合读：编排层的每一次「重读一遍确认没变」都有成本，要么算进账单，要么用租约把它变成一次。
